# Project Memory Skill

如果你用 AI 长期维护同一个项目，可能遇过这种情况：换一个会话，AI 读懂了代码，你却还得再解释一遍「我们为什么做这个功能」「上次为什么放弃那个方案」。代码能告诉接手的人最后实现了什么，做决定时考虑过的用户、约束和取舍却常常只留在聊天记录里。

Project Memory 帮你把这些会影响下一次决策的理由写进仓库。它适合跨多个会话工作的独立开发者，也适合多人或多个 AI 工具轮流接手同一代码库的团队。下次开工时，接手者可以沿用已确认的判断，把需要讨论的时间留给真正发生变化的问题。

## 为什么分成方向、边界和偏好

假设你在为经常断网的外勤人员做巡检工具，现在要决定照片怎么保存。三个层次分别回答三个问题：

| 层次 | 要回答的问题 | 巡检工具里的例子 |
| --- | --- | --- |
| **1. 项目方向** | 为谁解决什么问题？什么结果算成功？据此判断一项工作值不值得做。 | 外勤人员要在现场完成巡检。断网时也能提交完整记录，才算完成任务。 |
| **2. 项目边界** | 为了达到目标，所有方案都必须守住什么约束？据此排除不可接受的方案。 | 照片是验收凭据。即使断网或关闭应用，已提交的记录也必须能找回照片，因此只保存在内存里的方案不能采用。 |
| **3. 项目偏好** | 几个方案都满足边界时，通常选哪个？为什么？什么情况下换一种做法？ | 为了方便维护，默认复用已有的本地存储。如果实测容量无法满足一次巡检，再评估专用存储。 |

下次有人提议引入专用存储时，团队可以直接讨论容量证据。原先选择本地存储的理由可以重议，照片必须可找回的要求仍适用于新方案。把取舍的理由和适用条件一起记下来，接手者才知道哪些决定可以自己做，哪些变化需要请项目负责人拍板。

## 这些判断怎么留给下一次会话

跨模块共用的方向、边界和偏好放在根目录的 `PROJECT-MEMORY.md`，每次开工先读。小项目可以直接在总纲里记关键经验。模块增多或总纲接近 2,000 字时，再把模块特有的约束、取舍和经验放进 `docs/memory/<topic>.md`（每册约 3,000 字），并在总纲注明做什么任务时要读哪一册。

收尾时，AI 按原有范围记录用户已拍板的决定。从一次实现中推断出的长期规则，要等用户确认才写入；符合现有边界的改动可以照常交付。已有较长的记忆文件时，可参照[迁移说明](skills/project-memory/references/migration.md)。

## 安装

克隆本仓库后，按你使用的工具整目录复制安装（含 `references/` 子目录；Cursor 会自动加载 `~/.codex/skills` 与 `~/.claude/skills`）：

```sh
# Codex
mkdir -p ~/.codex/skills/project-memory
cp -R skills/project-memory/. ~/.codex/skills/project-memory/

# Claude Code
mkdir -p ~/.claude/skills/project-memory
cp -R skills/project-memory/. ~/.claude/skills/project-memory/

# 仅使用 Cursor（未装上面两项时）
mkdir -p ~/.cursor/skills/project-memory
cp -R skills/project-memory/. ~/.cursor/skills/project-memory/
```

新项目建档或点名迁移存量长文，可在新会话中输入：

```text
用 $project-memory 为这个项目建档（若已有超长旧记忆则先在会话起草迁移方案，确认后再原子切换）
```

想看看已有记忆里有哪些重复、冲突或过时的条目，可以输入「用 `$project-memory` 检查项目记忆」。它会列出依据和整理建议，文件保持原样。

## 项目接入（推荐放进项目 `AGENTS.md`）

建议在项目根目录的 `AGENTS.md` 中放下面两行精简指针（`CLAUDE.md` 可通过 `@AGENTS.md` 共用；详细规则留在技能内单一维护，避免多处副本脱节）：

> - **项目记忆**：开工先读根目录 `PROJECT-MEMORY.md` 总纲，并按其中触发索引读取 `docs/memory/` 下的相关分册；缺少记忆文件时用 `project-memory` 建档。
> - **收尾检查**：有改动的会话在提 PR、合并或交付前按 `project-memory` 技能检查更新（纯问答与只读排查跳过）；具体准入、并发与确认规则以该技能为准。
