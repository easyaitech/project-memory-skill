# 存量长文迁移指南（总纲 + 分册）

本指南仅在**用户明确点名迁移**超长或「只追加」旧版 `PROJECT-MEMORY.md` 时使用。目标是在不丢失有效红线、不产生规则空窗、不阻塞在途开发分支的前提下，将单份膨胀文档平滑切换为「2,000 字总纲 + `docs/memory/<topic>.md` 分册」。

## 1. 原位起草（用户确认前不动原文件）

1. **保留现场**：检查 `git status`，保留他人未提交改动；在用户确认新总纲前，**原 `PROJECT-MEMORY.md` 保持原位不动**，确保并行开发窗口仍能读到现行边界。
2. **梳理与消歧**：通读旧文档及仓库现行 `AGENTS.md` / `CLAUDE.md` / `CONTEXT.md` / ADR：
   - 已写入 `AGENTS.md` 或代码硬闸的红线，不重复抄进总纲；
   - 同一主题前后改口的多条记录，以最新有效结论为准；含义有冲突或待确认的旧原则单列出来请用户裁定，确认前保留原意。
3. **起草完成标准**：在会话中向用户提交约 2,000 字以内的「新总纲草案 + 分册与归档索引」：
   - 总纲每条方向、边界、偏好均能指回旧文依据；
   - 项目每个主要业务模块在第四节索引中**要么指向已拆出的 `docs/memory/<topic>.md` 分册，要么明确写出「涉及该模块仍须按关键词查阅归档旧文」的兜底入口**。

## 2. 分册合并策略取舍（切换前定好）

- **总纲 `PROJECT-MEMORY.md` 绝不配 `merge=union`**：否则全篇改写或压缩时，在途分支只要在旧文件末尾追加一行，Git union 合并就会把整份旧长文静默拼回新总纲（且退出码为 0）。
- **分册 `docs/memory/*.md` 按仓库交付模式选择**：
  - **普通并发仓库（默认）**：不配 `merge=union`，日常可直接修订或删除过期经验，合入前对照目标分支核对。
  - **高并发 + 机器自动排队合并仓库**：仅给需要并行追加的活跃分册配置 `merge=union`，使排队脚本的白名单与文件范围一致。归档和独立原则文件放在匹配范围外。经验通过出处及关键词显式覆盖；并行覆盖相抵时核对依据。队列若无法在发布前核对合并后的原则区，将原则移到不启用 union 的文件并在分册顶部链接。

## 3. 确认后单次原子切换

获用户确认后，在**同一提交 / PR** 中一次性完成以下动作，消除新旧规则断档期：

1. **归档旧文**：将原 `PROJECT-MEMORY.md` 移至 `docs/memory/archive/YYYY-MM-DD.md`（保留完整历史备查）。
2. **落盘新总纲与首批分册**：写入已确认的新 `PROJECT-MEMORY.md`（含未拆模块的归档兜底入口）及首批已梳理完毕的分册。
3. **全仓检索并切换旧约定**：在全仓检索 `PROJECT-MEMORY`、`merge=union`、`只追加` 等关键词（覆盖 `AGENTS.md`、`CLAUDE.md`、`.gitattributes`、发布/排队脚本、CI、收尾协议文档及代码注释），将每一处旧文件名或旧读写规则同步更新或确认兼容。
4. **在途分支**：列出仍对旧根文件有增量的分支；对照各自分叉点识别新增或修订的条目，按准入与确认规则转入活跃分册，或说明重复、过期等排除原因。旧分支基于新主线重放后再入队。

### 切换前演练自动队列

在临时仓库或隔离副本调用项目实际的本地合并入口，禁用推送和部署。准备共同基线，从它分出两支：旧 PR 在长文末尾追加一条带唯一标识的有效经验，目标主线改成已确认的短总纲并建立归档和分册。

- 模拟现役及复用工作目录，保留旧队列可能遗留的 `info/attributes`。在队列检出待合分支、写入自身属性之后、合并之前，用 `git check-attr merge -- <路径>` 逐个检查根文件、分册、归档及独立原则文件。核对队列实际运行的脚本版本；旧分支的仓库属性可通过重放分支修正；队列本地残留或运行时重新注入的旧规则须在队列端修正，保留无关属性。再次运行队列并确认根文件的有效策略已退出 union，即使某次合并内容恰好正确也要核验这一点。
- 让旧 PR 走一遍队列。允许它明确退回要求重放；禁止把错误的合并结果放行。按上一步迁好增量后重新入队，验证实际候选提交：根文件与预期短总纲逐字一致，归档保留原基线，标识经验在对应活跃分册恰好出现一次，业务改动保留。合并返回成功本身不足以验收。
- 使用 union 分册时，再合并两个同册追加：独立经验应各保留一次；若两条同时覆盖同一经验且相互矛盾，或被删除的旧原则重新出现，应在进入主干或发布前识别。验收结果随迁移 PR 或任务记录保存。

## 4. 归档消化（只减不增）

- `docs/memory/archive/` 下的快照**只减不增**，新经验一律写进对应分册或总纲。
- **批量拆册**按模块在独立整理任务中进行（经验核实后迁入，模块边界经用户确认后置顶写入，更新总纲强触发索引）。
- **日常顺手搬迁**：日常任务仅在回查归档并核实了某条具体经验仍有效时，顺手将其迁入分册并从归档删除该条（搬一条删一条）；所有模块搬空后删除归档文件及总纲中的归档兜底入口。
